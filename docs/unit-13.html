13.1 第一座完整 PBL 專案

從本單元開始，把前面學的感測、判斷、輸出、記錄、教學法整合成一座完整專案。第一座：「環境感測站」。

專案定位：一座可以放在教室/家裡的裝置，持續量測光線與溫度，用可視化方式提醒與記錄。跨 S+T+M。

13.2 驅動問題與需求

範例
驅動問題：「教室的光線與溫度，適合學習嗎？」

需求（學生版）：
  1. 持續量測光線與溫度
  2. 光太暗/太亮時提醒（LED + 音效）
  3. 溫度過高時警示
  4. 可以回看一段時間的紀錄

13.3 里程碑規劃

週次里程碑產出
W1Engage + 需求定義驅動問題 + 需求清單
W2感測 + 顯示光/溫讀取 + 水銀柱顯示
W3判斷 + 警報門檻值 + 燈號/音效
W4記錄 + 測試收集數據 + 除錯
W5成果發表作品 + 數據報告 + 發表

13.4 技術整合骨架

程式骨架
變數：light, temp, state
forever:
  light = light level
  temp  = temperature
  顯示（水銀柱 or 數字切換）
  判斷：
    if light < 40:  提醒「太暗」→ 顯示 + 音效
    if temp > 32:   提醒「太熱」→ 顯示 + 音效
  記錄：每 5 秒存一筆（陣列，滿了顯示平均）
  pause 5000 ms
按鈕：
  A：切換顯示 光線/溫度
  B：顯示平均與最高/最低

13.5 數據報告與發表

  • 收集整天資料 → 表格 + 折線圖（可搬到電腦畫）。
  • 下結論：教室何時光線最差？需要什麼改善？
  • 發表：展示作品 + 說明「設計決定」。
Rubric 片段（單元 18 詳談）
維度        滿分   3 分描述
感測正確    3     三種顯示都正確運作
數據處理    3     有完整表格與結論
美觀/警報   3     燈號音效清楚有趣
發表說明    3     能解釋設計決定與改進
省思題：如果你的感測站被批評「顯示看不懂」，你會怎麼改進？

13.6 Worked Example：一天 45 分鐘課的感測站示範

範例
0-5'   ：展示「壞範例」（亂跳的顯示）→ 引導需求
5-15'  ：小組討論需求清單（引導出「顯示/提醒/記錄」）
15-30' ：分組實作（給程式骨架，各自調門檻）
30-40' ：組間互測（換組用不同條件測試）
40-45' ：省思 + 紀錄下一步（回饋單）

動手：列出你專案的需求清單，並為每個需求寫一個「測試方法」。

  • 規劃一個完整 PBL 專案的里程碑。
  • 整合感測、記錄與展示於一個作品。
  • 發表專案並解釋設計決定。

進階真實情境 Worked Example

以下是一個與上方不同的真實場景，展示多感測器 + 資料視覺化 + 跨裝置通訊的完整工作流。

進階 Worked Example
場景：「IoT 環境感測站」— 加入 WiFi 擴充板
目標：感測站不只本地顯示，還能將數據上傳到雲端平台

硬體升級：
  Micro:bit v2 + WiFi 擴充板（如 Pico:bit 或 ESP8266 模組）

工作流：
  1. 量測：光線 + 溫度 + 音量（每 30 秒一次）
  2. 本地顯示：LED 矩陣顯示「目前狀態」（正常/異常）
  3. 雲端上傳：透過 WiFi 將 JSON 格式資料送到 ThingsBoard
     格式：{"light": 180, "temp": 25, "sound": 95, "ts": 1690000000}
  4. 網頁儀表板：在 ThingsBoard 上建立即時圖表

跨裝置通訊設計：
  - 板子 A（感測）→ WiFi → 雲端 → 網頁
  - 板子 B（接收端）← 無線電 ← 板子 A
  - 雙路徑：有 WiFi 時上雲；沒 WiFi 時用無線電送到粼近板子

為什麼選這條路徑？
  → 雲端讓家長/校長也能看到即時數據
  → 本地 LED 顯示確保「斷網也能用」
  → 雙路徑是 IoT 韌性設計的基礎

深入原理擴充

從 Micro:bit 到 IoT：Micro:bit 本身沒有 WiFi，需要外接模組才能連上網路。常見的 IoT 架構：

架構元件適合複雜度
本地顯示Micro:bit 內建教室展示低
無線電 → 主控板 → 電腦2+ 台 Micro:bit校園監測中
WiFi → 雲端Micro:bit + WiFi 模組遠端監控高
藍牙 → 手機 APPMicro:bit v2 BLE個人裝置中
數據格式：JSON 是 IoT 的通用語言。教學生理解 {key: value} 的結構，這會在未來的 API 使用中反复出現。
症狀可能原因解決方案
WiFi 擴充板連不上WiFi 名稱/密碼錯誤確認 SSID 和密碼正確；注意大小寫
雲端收不到資料JSON 格式錯誤或 API Key 過期用序列埠先確認資料格式正確
感測值不穩定WiFi 通訊時電流波動影響 ADC加入電容穩壓；或在 WiFi 傳輸時暫停感測
無線電距離不夠2.4GHz 與 WiFi 頻段衝突使用不同群組號；或拉開 WiFi 路由器距離
電池消耗太快WiFi 模組持續搜尋網路設定固定的上傳間隔（如 60 秒），其餘時間關閉 WiFi

進階挑戰題

  1. 資料壓縮：你的感測站每 30 秒上傳一次資料，每次 3 個數值。如果要連續運行一學期（18 週 × 5 天 × 6 小時），總共產生多少筆資料？設計一個「壓縮策略」（例如：只上傳「變化時」的資料），計算能節省多少頻寬。
  2. 斷網韌性：設計一個「本地快取」機制：當 WiFi 斷線時，資料先存在 Micro:bit 的陣列中；連線恢復後再批量上傳。最多能存多少筆資料？
  3. 隱私與安全：如果感測站收集的是教室音量數據，有哪些「隱私考量」？設計一個「去識別化」策略（例如：只記錄「音量等級」而非原始音訊）。

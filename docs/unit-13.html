13.1 第一座完整 PBL 專案

從本單元開始，把前面學的感測、判斷、輸出、記錄、教學法整合成一座完整專案。第一座：「環境感測站」。

專案定位：一座可以放在教室/家裡的裝置，持續量測光線與溫度，用可視化方式提醒與記錄。跨 S+T+M。

13.2 驅動問題與需求

範例
驅動問題：「教室的光線與溫度，適合學習嗎？」

需求（學生版）：
  1. 持續量測光線與溫度
  2. 光太暗/太亮時提醒（LED + 音效）
  3. 溫度過高時警示
  4. 可以回看一段時間的紀錄

13.3 里程碑規劃

週次里程碑產出
W1Engage + 需求定義驅動問題 + 需求清單
W2感測 + 顯示光/溫讀取 + 水銀柱顯示
W3判斷 + 警報門檻值 + 燈號/音效
W4記錄 + 測試收集數據 + 除錯
W5成果發表作品 + 數據報告 + 發表

13.4 技術整合骨架

程式骨架
變數：light, temp, state
forever:
  light = light level
  temp  = temperature
  顯示（水銀柱 or 數字切換）
  判斷：
    if light < 40:  提醒「太暗」→ 顯示 + 音效
    if temp > 32:   提醒「太熱」→ 顯示 + 音效
  記錄：每 5 秒存一筆（陣列，滿了顯示平均）
  pause 5000 ms
按鈕：
  A：切換顯示 光線/溫度
  B：顯示平均與最高/最低

13.5 數據報告與發表

  • 收集整天資料 → 表格 + 折線圖（可搬到電腦畫）。
  • 下結論：教室何時光線最差？需要什麼改善？
  • 發表：展示作品 + 說明「設計決定」。
Rubric 片段（單元 18 詳談）
維度        滿分   3 分描述
感測正確    3     三種顯示都正確運作
數據處理    3     有完整表格與結論
美觀/警報   3     燈號音效清楚有趣
發表說明    3     能解釋設計決定與改進
省思題：如果你的感測站被批評「顯示看不懂」，你會怎麼改進？

13.6 Worked Example：一天 45 分鐘課的感測站示範

範例
0-5'   ：展示「壞範例」（亂跳的顯示）→ 引導需求
5-15'  ：小組討論需求清單（引導出「顯示/提醒/記錄」）
15-30' ：分組實作（給程式骨架，各自調門檻）
30-40' ：組間互測（換組用不同條件測試）
40-45' ：省思 + 紀錄下一步（回饋單）

動手：列出你專案的需求清單，並為每個需求寫一個「測試方法」。

看完這單元你應該能說出：
  • 規劃一個完整 PBL 專案的里程碑。
  • 整合感測、記錄與展示於一個作品。
  • 發表專案並解釋設計決定。

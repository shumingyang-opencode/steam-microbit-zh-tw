6.1 什麼是事件驅動

傳統程式「從頭跑到尾」；事件驅動程式則「一直待命，事件發生時才執行對應程式碼」。

模式比喻範例
順序程式照食譜一步一步做顯示 → 等待 → 顯示
事件驅動客服電話，響鈴才接按 A 才執行、搖晃才執行
MakeCode 的事件積木：on button A pressed、on shake、on radio received、on logo pressed——都是「當…發生時」。

6.2 變數與狀態

  • 變數：記住數值（如計數器、狀態碼）。
  • 狀態：程式目前處於哪個「模式」。
範例
變數 count = 0
on button A pressed:
  count += 1
  show number count          ← 每按一次 +1

6.3 狀態機：讓行為有「模式」

狀態機用「狀態 + 轉換」組織行為：程式一次只處在一個狀態，事件讓它切換。

待機按A→顯示中按B→關閉按A→待機
範例
狀態 mode = "off"
on button A pressed:
  if mode == "off": mode = "on"; show icon 💡
  else:              mode = "off"; clear screen
on button B pressed:
  if mode == "on": show string "HELP"
為什麼要教狀態機：它是「程式邏輯」的核心思維，也連結數學的布林判斷與流程圖。

6.4 常見設計模式

  • 計數器：按一下 +1（練迴圈與變數）。
  • 切換開關：同一個按鈕開/關（狀態機最簡單應用）。
  • 多選單：按 A 換選項、按 B 確認。
陷阱：事件積木裡「只做很短的事」最好——太久會讓其他事件延遲。長時間任務放 forever。

6.5 Worked Example：三分鐘狀態機遊戲

範例
「心情切換器」
狀態：happy / sad / angry
on button A pressed:
  happy → sad → angry → happy（循環切換）
  依狀態顯示對應表情
on button B pressed:
  顯示目前狀態名稱（"I am HAPPY!"）

挑戰延伸：
  用「搖晃」隨機跳一個狀態 → 連結單元 10 的隨機數

動手：用狀態機做一個「三模式電筒」——關/暗/亮，按 A 循環切換。

看完這單元你應該能說出：
  • 解釋事件驅動與傳統順序程式的差異。
  • 用事件積木設計互動行為。
  • 用狀態機讓行為有「模式」。

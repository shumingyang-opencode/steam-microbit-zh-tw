10.1 數學在 Micro:bit 的日常

程式本身就是數學的應用：變數、邏輯、隨機、座標、統計。本單元把抽象的數學「放到手上」。

STEAM 的 M：讓學生在專案中「用」數學，比紙上練習更難忘——而且會開始追問「為什麼這樣算」。

10.2 隨機數

範例
電子骰子：
on shake:
  roll = pick random 1 to 6
  show number roll

抽籤選人：
on button A pressed:
  person = pick random 1 to class_size
  show number person
討論點：電腦的「隨機」真的是隨機嗎？（連結機率與公平性）

10.3 座標系統

  • LED 矩陣用 (x, y) 定位，x/y 各 0–4。
  • 可做「走迷宮」「搜尋寶藏」「向量移動」。
  • 連結數學：直角坐標、相對位置、距離。
範例
點亮一個「會跑的點」：
變數 x = 0
forever:
  unplot x, 2
  x += 1
  if x > 4: x = 0      ← 折返（取模）
  plot x, 2
  pause 200 ms

10.4 角度與羅盤

  • compass heading 回傳 0–359 度（需校準）。
  • 用方向角做「導向遊戲」：面向北方時亮綠燈。
  • 連結數學：方位角、旋轉。

10.5 統計：平均與範圍

範例
收集 10 個光線讀值算平均：
變數 sum = 0
on button A pressed:          ← 每按一次記一個
  sum += light level
  count += 1
on button B pressed:
  show number sum / count     ← 平均亮度

延伸：用陣列（list）存下所有值，顯示「最高/最低/平均」。

10.6 Worked Example：座標尋寶

範例
遊戲：「找亮點」
  1. 隨機藏一顆 LED（target_x, target_y）
  2. 玩家按 A/B 移動「玩家點」在 5×5 上走
  3. 到達藏點 → 亮笑臉 + 計分
  4. 統計：走幾步找到（用變數 steps 計數）

數學連結：座標、距離（曼哈頓距離）、機率（藏點隨機）。

動手：做一個「電子骰子 + 平均紀錄」，搖 10 次算平均，討論為何不一定接近 3.5。

10.7 數學教案片段：從隨機到公平

40 分鐘活動
5'   預測：搖 12 次骰子，六個點數各會出現幾次？
10'  實作：每組記錄 12 次結果，算總和、平均、眾數與範圍
10'  合併：全班把資料放在同一張表，比較小樣本與大樣本
10'  改造：加入「重搖」規則，討論它是否仍然公平
5'   出口票：用一句話解釋平均值接近 3.5 不代表每次都會是 3 或 4
概念學生要說清楚
平均值總和除以次數，是一組資料的集中位置
範圍最大值減最小值，描述分散程度的簡單指標
公平性每個結果機會相同；不能只看一次實驗下結論

練習：把「找亮點」改成兩人版：一人控制玩家，一人記錄每局步數；收集 10 局後比較平均步數，並提出一個讓遊戲更公平的規則。

  • 用座標系統定位 LED。
  • 用角度與簡單統計解決問題。

進階真實情境 Worked Example

以下是一個與上方不同的真實場景，展示多感測器 + 資料視覺化 + 跨裝置通訊的完整工作流。

進階 Worked Example
場景：「班級公平抽籤器 + 統計驗證」
目標：做一個「公平抽籤器」，並用統計方法驗證它是否真的公平

Step 1：基本抽籤器
  on button A pressed:
    name = pick random 1 to 30    ← 代表 30 個學生
    show number name

Step 2：統計驗證
  變數 counts = [0,0,0,...,0]     ← 30 個位置全為 0
  on button A pressed:
    name = pick random 1 to 30
    counts[name-1] += 1
    show number name
  on button B pressed:
    顯示被抽到最多次的人的編號

Step 3：視覺化分佈
  用 LED 矩陣畫「次數分佈圖」
  - x 軸 = 學生編號（0-4 代表 5 人一組）
  - y 軸 = 被抽到的次數（0-4）

Step 4：統計分析
  按 A+B 顯示：平均次數、標準差、最大值-最小值
  討論：如果某人被抽到 5 次、某人 0 次，這公平嗎？

設計路徑：
  → 不只做「抽籤」，還要「驗證公平性」
  → 數學從「算平均」延伸到「分佈」與「標準差」
  → 連結真實問題：抽籤公平嗎？樣本夠大嗎？

深入原理擴充

電腦隨機數的本質：電腦產生的「隨機數」實際上是偽隨機數（Pseudo-Random Number Generator, PRNG）。MakeCode 的 pick random 使用線性同餘法（Linear Congruential Generator），公式為：

next = (a × current + c) mod m

其中 a、c、m 是固定常數。只要起始種子（seed）相同，產生的「隨機」序列就完全相同。這就是為什麼 Micro:bit 每次開機後的「隨機」序列可能很相似——因為種子通常基於系統時鐘，而開機時間很接近。

教學連結：這是教「偽隨機 vs 真隨機」的絕佳機會。可以問學生：「如果老師知道你的起始條件，能預測你的隨機結果嗎？」這連結到資訊安全（加密）的概念。
症狀可能原因解決方案
每次開機的「隨機」序列都一樣PRNG 種子固定（系統時鐘相近）用加速度計讀值作為種子（每次不同）
骰子 6 個面出現次數差很多小樣本的正常波動增加測試次數（100+ 次）；用全班數據合併
pick random 範圍搞錯從 0 开始還是從 1 開始注意：MakeCode 的 pick random 1 to 6 包含 1 和 6
平均值計算結果偏差大整數除法截斷用 sum * 10 / count 放大後計算，或改用 MicroPython
統計量超出 LED 顯示範圍數字太大 5×5 LED 看不清用 show string 捲動顯示；或顯示近似值

進階挑戰題

  1. 蒙地卡羅模擬：用 Micro:bit 的隨機數估計 π 值：在 5×5 的「正方形」中隨機撒點，統計落在「四分之一圓」內的比例。比例 × 4 ≈ π。你的估計值離 3.14 多遠？需要多少次才能穩定？
  2. 偏差實驗：設計一個「有偏差的骰子」（某些數字出現機率更高）。用 100 次測試驗證你的偏差，並計算每個面的「觀測機率 vs 理論機率（1/6）」的差距。
  3. 加密入門：用隨機數做一個簡單的「凱撒密碼」加密器：按 A 輸入字母（用 LED 顯示目前字母），按 B 確認，最後顯示加密後的結果。討論：如果加密鑰匙是隨機的，接收者怎麼知道鑰匙？

9.1 從內建走向外接

內建感測器能「感知」，但要做出真正的工程作品（會動、會叫、會感測環境），需要外接元件。

P0/P1/P2→LED/蜂鳴器/伺服馬達/外接感測器

9.2 基本外接元件

元件接法程式用途
外接 LED腳位 → P0，另一腳 → GNDdigital write P0 (1/0)紅綠燈、指示燈
蜂鳴器腳位 → P0play tone at P0警報、音效
伺服馬達訊號線 → P0servo write P0 角度艙門、轉向
外接感測器訊號 → P0，VCC/GNDanalog read P0超音波、土壤濕度
安全：外接電路請先由老師檢查；確認極性與電阻（LED 串電阻避免過電流）。

9.3 擴充板與模組化

  • 擴充板（Shield）：把 25 個接腳轉成排針或 Grove 介面，插拔方便。
  • Grove / Octopus 模組：標準化的感測器模組（LED、超音波、濕度…），一條線接好。
  • 優點：學生不易接錯、節省時間、專注在「設計」而非「接線」。
工程思維：模組化 = 標準介面 + 可替換元件。讓學生觀察「為什麼擴充板讓工作變快」。

9.4 工程設計流程（EDP）

  1. 問：要解決什麼問題？
  2. 想像：有哪些方案？
  3. 計畫：畫出設計圖。
  4. 建立：組裝與接線。
  5. 測試：跑起來、除錯。
  6. 改進：修正後重測。
與 PBL 的關係：EDP 是 PBL 中「做出作品」那段的核心方法論。

9.5 Worked Example：聲控警報器

範例
問題：安靜的教室裡，有人尖叫怎麼辦？（防霸凌情境）

設計：
  輸入：麥克風（音量）
  判斷：音量 > 150 持續 1 秒
  輸出：LED 閃紅燈 + 蜂鳴器響 + 顯示 "HELP"

程式骨架：
on start: pin P0 = 蜂鳴器
forever:
  if sound level > 150:
    for 5 次: digital write P0 1 → 亮/響 200ms → 0 → 200ms
    show string "HELP"
    pause 5000 ms      ← 冷卻避免重複觸發

測試與改進：誤觸發太多？→ 提高門檻；太安靜？→ 降低。

動手：用外接 LED + 蜂鳴器做一個「光暗警報器」，並走完 EDP 六步驟寫下記錄。

看完這單元你應該能說出：
  • 用接腳外接 LED 與蜂鳴器。
  • 說明擴充板與 Grove 的作用。
  • 完成一個外接硬體工程專案。

進階真實情境 Worked Example

以下是一個與上方不同的真實場景，展示多感測器 + 資料視覺化 + 跨裝置通訊的完整工作流。

進階 Worked Example
場景：「光追蹤太陽能板」— 用兩顆光感測器 + 伺服馬達
目標：太陽能板（用伺服馬達帶動）自動朝向光線最強的方向

硬體：
  - 2 顆外接光敏電阻，分別接在 P0（左）和 P1（右）
  - 伺服馬達接在 P2，帶動一個小平台（模擬太陽能板）
  - Micro:bit 做控制核心

工作流：
  forever:
    left = analog read P0      ← 左側光線
    right = analog read P1     ← 右側光線
    diff = left - right

    if abs(diff) > 20:         ← 差異夠大才轉（避免震盪）
      if diff > 0:             ← 左邊較亮
        angle += 5             ← 向左轉 5 度
      else:
        angle -= 5             ← 向右轉 5 度
      angle = max(0, min(180, angle))  ← 限制範圍
      servo write P2 angle
    pause 500 ms

工程設計決策：
  → 為什麼加「死區」（abs(diff) > 20）？
  → 因為伺服馬達在微小差異下會不斷反覆轉動（震盪）
  → 死區讓系統在「差異不大時」保持穩定

深入原理擴充

PWM 與伺服馬達：伺服馬達（Servo）接收 50Hz 的 PWM 訊號，脈衝寬度決定角度：

脈衝寬度馬達角度用途
0.5 ms0°左極限
1.5 ms90°中間位置
2.5 ms180°右極限

MakeCode 的 servo write P0 to 90 積木底層就是設定對應的脈衝寬度。Micro:bit 的 GPIO 可以產生約 50-100Hz 的 PWM，足以驅動小型伺服馬達。

陷阱案例：「伺服馬達抖動不停」——很多人以為是馬達壞了，其實是你的程式在不斷改變角度。如果 forever 迴圈中沒有「死區」或「穩定判斷」，馬達會在微小差異之間來回震盪。解決方案：加入死區（如 abs(diff) > 20 才動作）、加入 pause（讓馬達有時間穩定）、以及使用「目標角度」而非「每步都轉」的控制策略。
症狀可能原因解決方案
伺服馬達抖動不停程式不斷改變角度（無死區）加入 abs(diff) > threshold 的穩定判斷
馬達轉到極限卡住角度超出 0-180 範圍用 max(0, min(180, angle)) 限制範圍
外接 LED 不亮未接電阻或極性接反LED 串 220Ω 電阻；確認長腳接 3V、短腳接 GND
analog read 值全為 0感測器未正確連接確認 VCC→3V、GND→GND、Signal→P0/P1
馬達只轉不回程式中角度只加不減檢查控制邏輯，確保雙向都能轉動

進階挑戰題

  1. PID 控制入門：在你的光追蹤系統中加入「積分」（I）項：不只看「目前差異」，還累積「過去所有差異」。當差異持續存在時，加速轉動。比較：有 I 項 vs 沒 I 項的追蹤效果有何不同？
  2. 雙軸追蹤：擴充你的系統到「雙軸」：用兩顆伺服馬達分別控制水平（左右）與垂直（上下）旋轉。你需要幾顆光感測器？如何決定旋轉方向？
  3. 功耗分析：測量伺服馬達在不同負載下的電流消耗（如果有電流表）。當馬達「hold position」vs「actively turning」時，電流差多少？這對電池供電的專案有什麼影響？

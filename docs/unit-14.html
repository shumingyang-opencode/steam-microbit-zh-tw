14.1 第二座完整專案：互動遊戲

第二座 PBL 專案：設計一款可以玩的遊戲——需要「規則設計」（工程/邏輯）與「樂趣」（藝術/動機）。

STEAM 連結：遊戲設計是「工程（規則與平衡）+ 藝術（呈現與樂趣）+ 數學（計分與機率）+ 科技（實作）」的完美綜合。

14.2 遊戲設計要素

要素問題Micro:bit 例子
目標玩家要達成什麼？接到最多的「星星」
規則能做/不能做什麼？只能用按鈕移動、不能搖
挑戰難度在哪？星星越掉越快
回饋玩家怎麼知道結果？LED + 音效 + 計分
樂趣為什麼好玩？反應競速、多人對戰

14.3 一個簡單遊戲：接星星

範例
狀態：playing / gameover
on start: 分數=0, 顯示"GO"
forever:
  if playing:
    星星從頂部落下（變數 star_y 遞增）
    玩家位置（player_x）由 A/B 左右移動
    碰撞（player_x == 星星 x 且 player_y == star_y）
      → 分數+1，音效
    落到底沒接 → gameover
on gameover:
  顯示分數 + "GAME OVER"

14.4 計分、生命與難度

  • 計分：接到 +1，miss 扣生命。
  • 生命：3 條命，沒了 → gameover。
  • 難度：分數越高，星星掉越快（用變數控制 pause）。
範例
難度公式：speed = 300 - score * 10   ← 分數越高越快
（數學連結：線性關係！）

14.5 多人對戰（無線電）

範例
雙人對戰「誰先搖到 10 次」：
  各自：on shake → 次數+1 → 廣播自己的次數
  互相接收：顯示「我：X 對手：Y」
  先到 10 → 廣播 "WIN"
（整合單元 11 無線電 + 單元 6 狀態機）

14.6 Worked Example：完整「接星星」規格

範例
遊戲：STAR CATCHER
目標：接住掉落的星星，分數越高越好
規則：A/B 移動玩家；星星每 300ms 落一格；
      接到 +1；漏接生命-1（3 條命）
回饋：接到→音效+閃爍；漏接→警示音
結束：生命=0 → 顯示總分 → 搖晃重來
難度：速度 = 300 - 分數*8（下限 100ms）

分組分工（工程思維）：
  設計師：規則與關卡
  程式員：移動/碰撞
  測試員：找 bug（故意連按、猛搖）

動手：先畫一張你遊戲的「規則 + 狀態圖」（狀態機），再開始寫程式。

進階真實情境 Worked Example

以下是一個與上方不同的真實場景，展示多感測器 + 資料視覺化 + 跨裝置通訊的完整工作流。

進階 Worked Example
場景：「雙人對戰遊戲」— 用無線電做即時對戰
遊戲：「太空射擊戰」

玩家 A（太空船）：
  - A/B 控制上下移動
  - 搖晃發射「飛彈」（radio send "SHOOT"）
  - LED 顯示太空船位置

玩家 B（衛星）：
  - A/B 控制左右移動
  - 被射中 → radio send "HIT" → 分數 -1
  - LED 顯示衛星位置

計分系統：
  - A 射中 B：A 得 1 分
  - B 躲過（飛彈到達邊界沒中）：B 得 1 分
  - 先得 5 分者勝

遊戲平衡：
  - 飛彈速度：400ms/格（太慢 B 容易躲、太快 A 容易中）
  - 移動速度：200ms/格（與飛彈速度的比例決定遊戲節奏）
  - 飛彈位置：從 A 的位置直線飛向 B 的 Y 座標

數學平衡公式：
  hit_rate = f(飛彈速度, 移動速度, 畫面大小)
  → 目標：hit_rate ≈ 30-40%（不會太難也不會太簡單）

深入原理擴充

遊戲平衡的數學：一個好的遊戲需要「挑戰性」與「可達成性」的平衡。這可以用數學模型來分析：

參數公式影響
命中率飛彈速度 / 移動速度 × 畫面寬度太高→太容易、太低→太難
遊戲節奏1 / (飛彈間隔 + 移動間隔)太快→反應不及、太慢→無聊
難度遞增speed = base - score × kk 太大→後期太難、k 太小→無挑戰
連結真實世界：遊戲平衡就是「系統思維」——每個參數改變都會連動其他參數。這和工程設計、經濟學的「均衡」概念相通。
症狀可能原因解決方案
遊戲太難（一直輸）對手移動太快或飛彈太慢調整速度參數；加入「起始優勢」（如：落後者飛彈加速）
遊戲太簡單（一直贏）飛彈太快或對手太慢反向調整；或加入障礙物增加複雜度
多人遊戲不同步無線電延遲導致位置不同步用「最終位置」而非「每步同步」；加入延遲補償
計分系統有 bug分數變數未初始化或範圍錯誤確保 on start 初始化分數；用 max(0, score) 防止負分
遊戲結束判斷失敗結束條件未覆蓋所有情況列出所有結束條件（先到 N 分、時間到等）並逐一檢查

進階挑戰題

  1. 難度曲線設計：在你的遊戲中加入「三關」：第一關速度 400ms、第二關 300ms、第三關 200ms。每關之間過渡時顯示「LEVEL UP」。畫出「關卡 vs 遊戲速度」的折線圖，討論：這條曲線「公平」嗎？
  2. 遊戲經濟學：設計一個「商店系統」：玩家在遊戲中收集金幣（接住星星），可以在「暫停」時購買升級（如：飛彈加速、 shield）。設計升級的價格，讓玩家不能在第一關就買到最強裝備。
  3. 玩家體驗研究：邀請 5 個同學測試你的遊戲，記錄每個人的「第一次遊玩分數」和「第五次遊玩分數」。學習曲線是什麼形狀？你需要調整什麼參數讓新手更容易上手？

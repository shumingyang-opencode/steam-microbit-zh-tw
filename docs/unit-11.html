11.1 無線電：讓板子彼此對話

Micro:bit 內建無線電（Radio），可在同群組的板子間傳送文字/數字，是「多板協作與對戰」的關鍵。

板子 Aradio send↔radio received板子 B

11.2 基本積木

積木功能
radio set group 1設定群組（同群組才互通，0–255）
radio send string "hello"廣播文字
radio send number 42廣播數字
on radio received receivedString收到文字時觸發
on radio received receivedNumber收到數字時觸發
分組管理：不同小組用不同 group，避免互相干擾——這本身就是「網路分組」概念。

11.3 三種典型應用

  • 投票/選擇：每台板子送自己的選擇，主控板統計。
  • 遙控：一台板子發方向，另一台（接伺服馬達）執行。
  • 對戰：多台板子互送攻擊訊息，計分顯示。

11.4 Worked Example：班級投票器

範例
學生板（每人一台）：
  on button A pressed: radio send "A"
  on button B pressed: radio send "B"
  on shake:            radio send "C"

老師板（主控）：
  radio set group 7
  變數 countA=0, countB=0, countC=0
  on radio received string:
    if 收到 "A": countA += 1
    if 收到 "B": countB += 1
    if 收到 "C": countC += 1
    顯示 A=... B=... C=...
教學連結：即時投票立刻建立「資料視覺化」與「統計」的課堂情境。

11.5 無線電的限制

  • 距離有限（約 10–20 公尺，室內更短）。
  • 同時廣播可能碰撞（訊息遺失）。
  • 電源會耗較快。
實務：對戰/投票專案最好先「小範圍」測試；重要的訊息可多送一次或用確認回覆。

11.6 Worked Example：無線遙控車

範例
遙控器板：
  on button A: radio send "L"（左轉）
  on button B: radio send "R"（右轉）
  on shake:    radio send "GO"（前進）

車子板（接伺服馬達 + LED）：
  radio set group 5
  on radio received string:
    if "L": servo P0 轉 45°
    if "R": servo P0 轉 135°
    if "GO": 前進動畫 + 亮燈

動手：做一個雙人「剪刀石頭布」——搖晃選拳，互送結果，主控板判勝負。

進階真實情境 Worked Example

以下是一個與上方不同的真實場景，展示多感測器 + 資料視覺化 + 跨裝置通訊的完整工作流。

進階 Worked Example
場景：「教室即時問答競賽」— 20 台板子同時回答
目標：老師出題，20 個學生同時按 A/B/C 選擇，主控板統計並即時顯示

技術挑戰：
  - 20 台同時廣播 → 無線電碰撞（collision）機率極高
  - 需要「防碰撞機制」避免資料遺失

解決方案：「時槽分配」（Time Slot）
  主控板（老師）：
    radio set group 1
    變數 question = 0
    on button A pressed:
      question += 1
      radio send question    ← 廣播題號

  學生板：
    radio set group 1
    變數 my_slot = 0         ← 每台板子用不同時槽
    變數 my_answer = 0

    on radio received receivedNumber:
      if receivedNumber == my_slot:
        按下按鈕時：radio send answer

  為什麼選時槽？
    → 簡單：每台板子分配 1-20 的時槽，輪流回答
    → 碰撞率低：同一時槽只有一台板子
    → 缺點：20 人要等 20 個時槽，較慢
    → 替代方案：隨機等候 + 碰撞重傳（更複雜但更快）

深入原理擴充

無線電碰撞問題：Micro:bit 的無線電使用 2.4GHz 頻段，基於 IEEE 802.15.4 協定。當多台板子同時廣播時，訊號會互相干擾（collision），導致接收端收到雜訊或丟失訊息。這與「網路塞車」原理相同。

碰撞處理策略原理適合場景
時槽（Time Slot）每台板子分配專屬時段人數固定、可預先分配
CSMA（載波偵聽）先聽有沒有人在講，有就等人數不定、需要即時性
重傳 + ACK發送後等待確認，沒收到就重傳需要可靠傳輸
連結真實世界：這就是 Wi-Fi 和行動網路的核心問題。你的手機能同時上網，就是因為它用了比 Micro:bit 複雜得多的碰撞處理協定。
症狀可能原因解決方案
多人同時廣播時資料遺失無線電碰撞（最常見問題）加入時槽機制；或用「按順序回答」的規則
板子收不到訊息群組號碼不同確認所有板子用 radio set group 同一數字
訊息延遲 1-2 秒無線電模組初始化需要時間在 on start 設定群組；避免在 forever 中重複設定
只收到部分板子的訊息距離太遠或有障礙物縮短板子間距離；移除金屬障礙物
電池消耗很快無線電模組持續運作在不需通訊時關閉 radio；或用更短的廣播間隔

進階挑戰題

  1. 可靠投票系統：改進班級投票器，加入「確認機制」：主控板收到投票後回傳「收到」，學生板沒收到確認就重傳。比較：有確認 vs 沒確認的投票完成率差異。
  2. 無線電距離實驗：在不同環境（教室、操場、走廊）測量無線電的有效距離。記錄：在什麼距離下開始丟訊息？什麼障礙物影響最大？畫出「距離 vs 成功率」圖表。
  3. 網狀網路入門：用 3 台 Micro:bit 做「中繼站」：板子 A 傳訊到板子 B，板子 B 再轉傳到板子 C。討論：這種「跳躍式傳輸」有什麼好處？有什麼風險（例如：延遲、單點故障）？

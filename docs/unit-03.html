3.1 兩種主流環境

環境模式適合特點
MakeCode
（Microsoft）		Blocks 方塊低年級/初學者拖拉積木，免記語法
JavaScript中高年級文字程式但保留方塊對照
Python進階方塊轉 Python 程式
MicroPython純文字高年級/進階Python 語法，直接寫程式
建議路徑：方塊（理解邏輯）→ JavaScript/Python 對照（理解語法）→ MicroPython（獨立開發）。同一塊板子可以陪你走完整段旅程。

3.2 MakeCode 介面入門

  • 編輯器：makecode.microbit.org（免安裝，瀏覽器即可）。
  • 模擬器：右側即時模擬，沒板子也能玩。
  • 下載：編譯成 .hex 檔 → 拖進板子即燒錄。
  • 積木分類：基本/輸入/音樂/LED/無線電/邏輯/迴圈/數學。
Hello World
on start ──▶ show string "Hello!"    （開機顯示文字）
on button A pressed ──▶ show icon 😀  （按 A 顯示笑臉）

3.3 燒錄流程（第一次上手）

  1. 用 USB 連接 Micro:bit → 電腦出現 MICROBIT 磁碟。
  2. 在 MakeCode 寫好程式 → 點「下載」。
  3. 把下載的 .hex 檔拖進 MICROBIT 磁碟。
  4. 板子自動重啟並執行；修改時重新下載即可。
常見問題：拖入失敗多半是 USB 線只充電不傳資料（請換「資料線」）；MAC 可能需要確認磁碟權限。

3.4 MicroPython 一瞥

範例
# microbit 官方 MicroPython
from microbit import *

while True:
    display.show(Image.HAPPY)
    if button_a.was_pressed():
        display.scroll("Hi!")
    sleep(100)

MicroPython 用 Mu 編輯器 或 Python Editor（python.microbit.org）寫作，燒錄方式類似。

3.6 課堂片段：同一功能，兩種語言

教案片段（25 分鐘）
0-5'   ：先在模擬器執行「按 A 顯示笑臉」
5-10'  ：學生把 Blocks 切換成 JavaScript，圈出相同的事件與動作
10-18' ：教師展示 MicroPython 版本，學生找出 import、if、while
18-23' ：練習：把笑臉改成「按 B 顯示愛心」
23-25' ：出口票：寫一句「我在除錯時先檢查什麼」

除錯檢查表：板子是否連線、事件是否選對、縮排是否一致、等待時間是否造成看不見的輸出。先在模擬器驗證，再下載到實體板，可把問題分成「程式」與「硬體」兩類。

練習：請在 MakeCode 完成「A 顯示 1、B 顯示 2、A+B 顯示 3」，再將其中一個事件改寫成 MicroPython；同伴只看執行結果猜是哪個事件。

  • 說出 MakeCode 三種模式與適用對象。
  • 說明 MicroPython 與 MakeCode 的差異。
  • 完成一次燒錄流程並執行 Hello World。

進階真實情境 Worked Example

以下是一個與上方不同的真實場景，展示多感測器 + 資料視覺化 + 跨裝置通訊的完整工作流。

進階 Worked Example
場景：「同一功能，兩種實作」— 用 MakeCode 與 MicroPython 各做一次
目標：按 A 顯示笑臉 + 播放音效，按 B 顯示哭臉 + 停止

MakeCode 版本：
  on button A pressed:
    show icon 😀
    play tone Middle C for 200ms
  on button B pressed:
    show icon 😢
    music stop

MicroPython 版本：
  from microbit import *
  import music

  while True:
      if button_a.was_pressed():
          display.show(Image.HAPPY)
          music.play(music.TONE_C)
      if button_b.was_pressed():
          display.show(Image.SAD)
          music.stop()
      sleep(50)

關鍵差異：
  1. MakeCode 用「事件積木」（中斷驅動），MicroPython 用「輪詢」（polling）
  2. MakeCode 的模擬器能即時預覽；MicroPython 需要 Mu 編輯器的序列埠回報
  3. 同樣的 .hex 檔，MakeCode 產生的通常較大（因為包含 runtime）
  4. MicroPython 允許更複雜的資料結構（list, dict），MakeCode 方塊較受限

為什麼選這條路徑？
  → 低年級用 MakeCode（視覺化、低門檻）
  → 高年級切換 MicroPython（培養文字程式能力）
  → 同一板子走完兩軌，是 Micro:bit 最大的教育優勢

深入原理擴充

MicroPython vs MakeCode 執行差異：

面向MakeCodeMicroPython
執行模型事件驅動 + 兩個主迴圈（forever + on start）單一 while True 迴圈 + 手動 polling
記憶體使用較高（MakeCode runtime 約 50-80KB RAM）較低（MicroPython kernel 約 30-50KB RAM）
執行速度中等（積木編譯為 JavaScript 再編譯）較慢（直譯器逐行執行）
檔案格式.hex（含 runtime + 程式碼）.hex（含 MicroPython kernel + .py）
除錯能力模擬器 + 視覺化高亮序列埠 print + Mu 編輯器
陷阱案例：很多人以為「MakeCode 切換成 Python 模式就等於 MicroPython」——這不完全正確。MakeCode 的 Python 模式底層仍然是 MakeCode runtime（JavaScript 引擎），只是語法改用 Python。它的效能、記憶體使用、與完整 Python 相容性都和 MicroPython 不同。例如：MakeCode Python 模式不支援 import math 的完整函式庫，而 MicroPython 可以。選擇時要理解這個差異。
症狀可能原因解決方案
MakeCode 下載後板子無反應USB 線只供電不傳資料換一條確認有資料傳輸功能的 USB 線
MicroPython 程式跑不動縮排錯誤（Python 對縮排敏感）用 Mu 編輯器的「Check」功能檢查語法；確認用空格不用 Tab
MakeCode 模擬器正常但實體板不動模擬器與實體硬體的時序差異加入 pause 等待；確認接腳/感測器在實體板上正確連接
MicroPython 出現 MemoryError程式碼太長或建立太多變數簡化程式碼、減少字串操作、使用更小的迴圈
MakeCode 的 JavaScript 模式看不懂方塊與文字語法的轉換不直覺先在 Blocks 模式完成，再切換 JavaScript 對照學習

進階挑戰題

  1. 效能基準測試：設計一個「計算密集」任務（例如：計算 1 到 1000 的平方和），分別在 MakeCode JavaScript、MakeCode Python、MicroPython 三種環境實作，比較執行時間。哪個最快？為什麼？
  2. 記憶體分析：在 MicroPython 中建立一個含 100 個整數的 list，用 sys.memory_usage()（或檢查 free memory）觀察記憶體使用量。再改用 array 模組存同樣的資料，比較兩者的記憶體差異。
  3. 跨環境移植：用 MakeCode 完成一個專案（例如計步器），嘗試用 MicroPython 實作完全相同的功能。記錄你在移植過程中遇到的 3 個主要差異，並解釋為什麼 MakeCode 的事件模型在某些場景下比 MicroPython 的 polling 更適合。

18.1 STEAM 怎麼評分

STEAM 作品沒有「唯一正確答案」，所以評量要分維度、看過程、看成長——這就是 Rubric 與 Portfolio 的用武之地。

評量哲學：評的是「學習」，不是「分數」。Rubric 先公開，學生才知道「什麼是好的」。

18.2 Rubric 設計四步驟

  1. 選維度（功能/設計/合作/發表…）。
  2. 定等級（通常 3–4 級）。
  3. 寫可觀察描述（每級看得見的行為）。
  4. 決定權重（哪些維度重要）。
Rubric 範例
維度：LED 動畫創意（權重 30%）
  4 有故事性、節奏佳、多幀流暢
  3 動畫清楚、有節奏變化
  2 動畫可動但單調
  1 無法呈現動畫

維度：程式正確性（權重 40%）
  4 功能全達 + 額外特色
  3 核心功能全運作
  2 部分功能
  1 無法運作

18.3 作品評量與互評

  • 作品展（Gallery Walk）：全班走一圈看彼此作品。
  • 互評卡：「我最喜歡 ___ 因為 ___」+ 一個建議。
  • 口頭發表：30 秒說明「我的設計決定」。
互評的原則：用「具體描述」不用「評分標籤」；建議要可執行（「可以試試把動畫放慢」）。

18.4 Portfolio：看成長

  • 收集：作品截圖/照片、學習單、省思、Rubric 回饋。
  • 對比：第一堂 vs 期末——「我學到了什麼」。
  • 數位化：拍下 LED 顯示照片，或用螢幕截圖。
省思題
每單元結束 1 分鐘省思（寫在學習單）：
  1. 這個作品我最滿意的部分是？
  2. 我卡住的地方是？後來怎麼解決？
  3. 下次我想挑戰什麼？

18.5 Worked Example：完整評量包

範例
【環境感測站 評量包】
1. Rubric（4 維度：感測/數據/警報/發表）
2. 互評卡（1 句讚美 + 1 個建議）
3. 學習單（需求、測試紀錄、省思）
4. Portfolio 頁（作品照片 + 過程照 + 3 句省思）

流程：實作完成 → 作品展 → 互評 → 老師 Rubric
      → 學生成績 = Rubric 60% + 省思/合作 40%

動手：為你的專案設計一份 Rubric（至少 3 維度 × 3 等級）。

看完這單元你應該能說出：
  • 設計一份可用的 Rubric。
  • 用作品評量與省思取代「唯一答案」。
  • 收集 Portfolio 展示成長。

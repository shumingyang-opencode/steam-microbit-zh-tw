16.1 一份 STEAM 教案的骨架

一份可執行的 STEAM 教案包含五大區塊：

區塊內容佔課堂比重
教學目標學生學完「能做到什麼」設計起點
活動流程5E 或步驟式活動80%
材料清單Micro:bit/元件/學習單準備
評量方式Rubric/作品/省思收尾
差異化不同程度學生的調整全程

16.2 教學目標怎麼寫

  • 用行為動詞：能「說出/做出/設計/比較/解釋」。
  • 可觀察：目標要是「看得見的表現」。
  • 帶條件與標準：在什麼情境、做到什麼程度。
範例
弱目標：「了解感測器」
強目標：「學生能使用 MakeCode 讀取光感測器數值，
         並在亮度低於 40 時讓 LED 顯示月亮圖案，
         準確率達 9/10 顆 LED 正確。」（可觀察、可評）

16.3 活動流程（結合 5E）

教案活動欄
活動（40 分鐘）
0-5  Engage：關燈情境劇 → 提問
5-15 Explore：玩 light level，記錄 3 種光線
15-25 Explain：討論門檻值 → 示範 if 積木
25-35 Elaborate：實作「月亮燈」+ 音效
35-40 Evaluate：同桌互測 + Rubric

16.4 材料與評量

  • 材料：Micro:bit ×N、USB 線、手電筒、學習單、Rubric 表。
  • 評量：Rubric（實作+合作）+ 學習單 + 課堂觀察。
常見錯誤：教學目標寫了但活動沒對應（目標要「驅動」活動）。每個活動都要能對到一個目標。

16.5 Worked Example：完整教案（月亮燈）

範例
教案：聲控月亮燈
年級：小學中年級 ｜ 時間：40 分鐘
目標：
  1. 能讀取 light level 並描述其範圍（S）
  2. 能用 if 積木依亮度判斷（T）
  3. 能設計「月亮/星星」LED 圖案（A）
材料：Micro:bit、USB 線、手電筒、學習單×2、Rubric
流程：
  0-5  Engage（關燈→提問「怎麼辦」）
  5-15 Explore（3 種光線實測紀錄）
  15-25 Explain（門檻值 + if 積木示範）
  25-35 Elaborate（實作 + 音效 + 圖案）
  35-40 Evaluate（互測 + Rubric + 省思 1 句）
評量：Rubric（功能 4 / 圖案 4 / 合作 3）
差異化：快的組加「自動亮度調整」；慢的組用預設圖案

動手：用教案模板寫一份你自己的 40 分鐘 STEAM 教案。

看完這單元你應該能說出：
  • 說出 STEAM 教案的五大區塊。
  • 撰寫清楚的教學目標（行為目標）。
  • 用模板產出一份完整教案。

進階真實情境 Worked Example

以下是一個與上方不同的真實場景，展示多感測器 + 資料視覺化 + 跨裝置通訊的完整工作流。

進階 Worked Example
場景：「逆向設計教案」— 從評量開始往回推
主題：「聲控月亮燈」教案逆向設計

Step 1：先定「最終評量」
  學生能獨立完成一個「光暗時自動亮燈」的裝置
  評量標準：10 次測試中 8 次正確觸發

Step 2：問「學生需要什麼能力才能做到？」
  能力 1：讀取 light level（S）
  能力 2：用 if 判斷亮度門檻（T）
  能力 3：設計 LED 圖案（A）
  能力 4：設定合適的門檻值（M）
  能力 5：測試與除錯（E）

Step 3：問「怎麼教這些能力？」
  → 能力 1-2：Explore 階段實測 + Explain 階段討論
  → 能力 3：Elaborate 階段實作
  → 能力 4：用數據引導（先量再決定門檻）
  → 能力 5：互測 + 除錯卡

Step 4：問「學生怎麼知道自己學會了？」
  → 即時回饋：模擬器看結果
  → 同伴回饋：互測卡
  → 教師回饋：Rubric 總評

為什麼選逆向設計？
  → 傳統「順向設計」容易「活動很多但沒對到目標」
  → 逆向設計確保「每個活動都指向評量」
  → 這是 Understanding by Design (UbD) 的核心方法

深入原理擴充

逆向設計（Backward Design）：由 Grant Wiggins 和 Jay McTighe 提出的 Understanding by Design (UbD) 框架，核心思維是「先決定學生要展示什麼能力，再設計教學活動」。

步驟傳統設計逆向設計
1選主題/活動決定預期結果（學生能做到什麼）
2設計活動決定評量證據（怎麼知道學生學會了）
3設計評量設計學習體驗（活動如何支持評量）
與 5E 的關係：5E 是「微觀」的教學流程；逆向設計是「宏觀」的教案架構。兩者可以結合：先用逆向設計確定「學生要能做什麼」，再用 5E 安排每堂課的活動流程。
症狀可能原因解決方案
教學目標太抽象（如「了解感測器」）沒用行為動詞改為「能使用 MakeCode 讀取光感測器數值」
活動與目標對不上順向設計的通病用逆向設計：先定評量標準，再問「什麼活動能幫助學生通過？」
學生說「做完但不知道在學什麼」缺少 Explain 階段在活動後加入「概念整理」（3 分鐘 Pair-Share）
評量無法反映真實能力Rubric 描述太籠統用「可觀察行為」重寫 Rubric 等級描述
差異化不足，快的等慢的活動只有一個版本設計「基礎→進階→挑戰」三層任務

進階挑戰題

  1. 逆向設計實作：選一個你即將要教的主題，用逆向設計法寫一份完整教案。包含：(1) 預期結果 (2) 評量證據 (3) 學習體驗。與你的「順向設計」版本比較，哪個更清晰？
  2. 教案同行審查：將你的教案交給另一位老師（或同伴），請他用「逆向設計」的三個步驟審查：目標是否明確？評量是否對應？活動是否支持評量？
  3. 差異化教案改造：為你的教案加入「三層差異化」：基礎版（所有學生）、進階版（完成基礎後）、挑戰版（完成進階後）。確保每層都有明確的「通過標準」。
